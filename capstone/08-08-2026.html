Session 20 — Manual Incident Authoring, and Two Routing Bugs Nginx Was Hiding

The biggest remaining gap in the whole project, and it wasn't close: every other workflow here got real polish, and creating a manual incident was still "open incidents.json by hand, commit, push, wait for a redeploy." That's closed now.

The schema was bigger than the scope doc

The plan said "add a source column." Actually building it surfaced that the table never stored a real title or affected-services list at all — auto-drafted incidents compute both from a single service_id at read time, which only ever worked because auto incidents are always single-service. A manual incident needs an arbitrary title and can span several services, so title and affected_services became real columns too, not just source. Existing rows backfilled correctly without a separate migration pass.

A real bug caught before it ever reached production

The auto-threshold's own dedup check — getActiveDraftedIncident — wasn't filtered by source. Left as-is, a manual incident sharing a service_id with a real active auto-drafted one would have looked like "already active" to the poller, silently suppressing a genuine auto-draft that should have fired. Caught during the build, fixed with one added clause, never actually happened in production — the good kind of bug story, the one where nothing broke because it got checked first.

Auth that cost zero application code

This project already runs entirely behind a Cloudflare Zero Trust tunnel, which made the actual auth decision easy: Cloudflare Access, gated specifically to /admin/*, with one Allow policy keyed to a single email. No password hashing, no session store, no login form in the admin page itself — Cloudflare validates identity at its own edge, before a request ever reaches nginx. One real, sharp finding along the way, worth remembering: publishing a tunnel route does not protect it by default. Until the Access application was actually created, /admin would have been reachable by anyone who guessed the URL — "the tunnel exists" and "the tunnel is protected" turned out to be two genuinely separate steps, not one.

Two real nginx bugs, both found live

The first attempt to load the admin page returned Express's own "Cannot GET /admin/" — the smoking gun that the request had reached the proxy container instead of being served as a static file. Root cause: nginx picks the longest matching prefix, and the original location /admin/ forward rule beat the generic catch-all for every request under that path, including the bare page load. Narrowed to the actual API path (/admin/incidents) specifically, the page request started falling through to static serving correctly.

Second bug, right behind it: the page loaded, but showed the public status page instead of the admin UI. location /'s try_files directive was missing its middle step — $uri/ — the piece that tells nginx to check whether a requested directory has its own index file before falling back to the root app. This gap was likely sitting in nginx.conf since the project's very first deploy; it simply never mattered until admin/ became the first real subdirectory anyone requested by path. Two bugs, same underlying cause — an nginx config that had never needed to route anything more complex than flat top-level paths before this feature.

Confirmed the way this project actually confirms things

All three write paths tested independently against real production, not just the happy path: a real incident created and rendering correctly on the live public page, a plain update posted and appearing as its own timeline entry (a genuinely different code path than resolving), and a resolve that flipped the status badge live. Cleanup followed the same pattern established with the Murloc SSE test — the real database ID pulled via /incidents, deleted directly, confirmed the live list back to exactly the real three incidents afterward.

Where this leaves things

The last big functional gap in the project is closed. What's left is smaller and more incremental — security hardening (now genuinely urgent, not just planned, since a real write-permission boundary is live), CI/CD, the embeddable badge, an architecture synthesis doc for presenting this to Perry, and a newly scoped layout change moving incidents into their own column. None of them carry the weight this one did.
