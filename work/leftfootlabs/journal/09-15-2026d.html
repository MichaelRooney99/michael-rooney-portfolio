The Bug That Explained Itself

Real fit validation shipped, which meant the placement feature it validates was finally finished enough to actually use rather than just build. Using it for real found two things no amount of planning had caught.

A bug whose cause was obvious once found

Placing two of the same keystone on one shelf and removing one of them removed both. The actual cause, once looked at directly, wasn't subtle: the remove function matched on the item's catalog id alone, and two placements of the same real item share that id by definition — the only thing that actually distinguishes them is where each one sits. The fix is real and specific (match on id and position together, not id alone), and the same root cause quietly applies to devices too, just less visible today since the catalog only has one real device that could ever be placed twice.

A real gap, not a bug

Separately: nothing dragged onto a shelf can be dragged again to move it — the only way to reposition something right now is remove it and place it over. A real fix, not a small one: the shelf face's existing items would need to become draggable themselves, with the drag payload distinguishing "moving something already there" from "placing something new from the picker."

Neither of these got fixed on the spot. Both are written down with their real cause and real shape, explicitly held for later rather than rushed in — a diagnosis is worth recording accurately even when the fix itself can wait.
