A Screenshot Isn't a Measurement

The faceplate data foundation shipped with two real numbers still genuinely unknown: what a keystone actually measures, and what a real "usable width" looks like on an actual shelf. Real reference files closed both gaps the same day — but only after the numbers already visible in a screenshot got checked against the actual files, not just trusted.

Reading the mesh instead of the picture

A slicer screenshot had already shown a tray at 254 by 133 by 44.426mm and a matching faceplate at 214 by 42.5 by 5mm. Those numbers could have been taken as given once the real STL and 3MF files arrived. Instead, the actual mesh geometry got parsed directly and its bounding box computed from scratch — the same numbers came back, which is exactly the point: the value isn't in catching a discrepancy that wasn't there, it's in the confidence being earned by checking rather than assumed because two sources happened to agree.

The first real number that wasn't null

Six shelves had been seeded so far with a real per-shelf field left honestly unmeasured, because nothing had actually measured it yet. This tray's real faceplate opening — 214mm — became the first real value for that field, seeded as a genuine seventh catalog entry rather than kept as a screenshot with no home in the actual data. The same real research that resolved the keystone question turned into a second real seeded fact: one universal keystone entry, 14.5 by 16.0mm, instead of an empty table waiting on a measurement that was actually already settled.

A real reference file sitting in a chat isn't the same thing as a real fact sitting in the database. The gap between those two is exactly the work that closed today.

What actually shipped

A height field added to the keystone table for a dimension that didn't exist an hour earlier, one real keystone row seeded with the actual standardized dimensions, and a seventh real shelf seeded with the first non-null usable-width value in the catalog — verified the same way every migration in this project has been: against a fresh database, and separately against a simulated existing one with real data already in it, confirming the new column backfills correctly rather than assumed.
