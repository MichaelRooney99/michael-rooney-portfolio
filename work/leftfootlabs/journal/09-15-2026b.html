The Choice That Stopped Being a Choice

The drag-and-drop placement work exposed something the shelf picker had been quietly doing wrong all along: offering seven named real shelf products to choose from, as if which one you picked actually changed anything about what gets built. It doesn't. Every one of them measures within a couple millimeters of the same real width — the whole reason that number counts as a standard in the first place.

A real fact hiding in plain sight

This wasn't a new discovery so much as a fact that had been sitting in the catalog's own evidence since the shelf model was first built, never applied to how the builder actually worked. Once it got named directly, the fix was obvious: stop asking someone to choose among products that don't meaningfully differ for the purpose of starting a layout, and use the one real shelf that already happens to measure exactly the standard width and height, rather than manufacturing a new abstract entry with invented dimensions to represent an idea that already had a real example sitting in the data.

A flag instead of a name

The tempting shortcut would have been a hardcoded id string in the interface saying which shelf counts as "the" one. That's exactly the kind of fragile, silently-driftable fact this project has avoided everywhere else — the rack-width standard itself is fetched from the server, not hardcoded twice, for the same reason. A real boolean column on the shelf itself, checked against a database with a real row already sitting in it from before the column existed, closes the same category of gap a very similar backfill mistake had already been caught and fixed once before.

The catalog didn't shrink. Seven real shelves are still there to browse. What changed is which question the builder actually needs an answer to before letting someone start.
