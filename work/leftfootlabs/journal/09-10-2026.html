The Kit Wasn't the Thing That Needed Checking

A validation feature meant to check whether a device fits a specific rack kit turned out to be checking the wrong entity entirely. The kit isn't something anyone places inside a layout — it's just how many rack units are available. What actually needs checking is the thing in between the rack and the device: the shelf.

The kit wasn't the thing that needed checking

The original plan validated layouts against "the kit" as a single monolithic item, which never had a clean answer for what a kit placed inside its own layout would even mean. The real hierarchy is rack → shelf → device, not rack → device: a frame only defines rail width and total rack-unit count, a shelf is the physical part that actually clips into those rails, and a device sits on a shelf rather than mounting to the rack directly. Reattaching both the universal fit check and the depth/weight capacity check to the shelf — instead of to an ambiguous kit reference — also answers a real product question: the runtime estimator work already proved real measured data beats an assumed number, and shelves are the part of this business a homelabber keeps buying long after a frame purchase, kit-owner or not.

What six real brackets confirmed

Photos and real slicer measurements of six independently designed 10-inch rack brackets — a Dell OptiPlex Micro mount, a TP-Link switch bracket, and a two-piece GMKtec mini PC mount among them — converged tightly on a 252–254mm width across every source, with zero convergence on depth. That's exactly the signature of a real rack standard: width is the constraint that makes something "10-inch rack compliant," depth is a property of whatever shelf you're looking at. The two-piece GMKtec design also surfaced a real distinction worth keeping straight going forward — an internal tray that holds a device isn't the same thing as the rack-facing faceplate it mounts behind, and only the faceplate's width is what actually gets checked against the standard.

One of the six sources' own measurements turned out to be an artifact, not real data — several slicer screenshots reported identical width and depth values, a strong tell of a diagonal-rotation bounding box from auto-arrange packing rather than the part's true dimensions. Worth catching before it became a permanently wrong seed row.

One plan, four independently buildable pieces

The full shelf model was too much to build in one sitting, so it split along its real dependency lines instead of an arbitrary line count: a foundation layer (new schema, types, and real seed data, purely additive), one unavoidably atomic restructuring step (reshaping how a layout represents what's placed where — the one piece that can't be split further without leaving the app broken in between), and two genuinely independent validation checks that can be built in either order once the restructuring lands. That last pair is the more interesting split — a rack-width check and a shelf-capacity check don't depend on each other at all, so treating them as one combined "kit compatibility" feature was never necessary in the first place.

The rule broken while writing the code that enforces it

Every comment explaining a real decision — why a lookup table instead of a hardcoded constant, why a particular tolerance value, why certain data got flagged as unmeasured instead of guessed — is supposed to carry its own reasoning, not point back at internal planning documents that won't exist in the same form a year from now. Six comments across four files did exactly that anyway, citing internal scope-doc filenames as shorthand instead of writing the actual reason out. Some were harmless once removed — the real explanation was already sitting right next to the reference and didn't need it. Others left a comment pointing at an explanation that no longer existed anywhere nearby, which needed the actual reasoning written in for the first time, not just a citation deleted.

What actually shipped

Two new database tables, a rewritten type module, a new data-access layer, six real non-leftfootLabs shelves seeded with real measured dimensions, and seven new tests — all verified against a real running database, not just a green test suite: a fresh seed inspected directly, and a simulated pre-existing database confirmed to actually drop the table it was supposed to retire rather than silently leaving it behind. Twenty-three of twenty-three tests passing, the same real-verification standard that caught a repeated-device wattage bug the session before this one.
