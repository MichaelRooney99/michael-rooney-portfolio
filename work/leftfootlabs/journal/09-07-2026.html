The Stylesheet That Was Never Attached

A styled panel that renders with zero visual difference from a plain unstyled form isn't necessarily a CSS bug — sometimes the CSS was never asked to run at all. That was the actual ending of this session, but it came after a genuinely useful stretch of real monorepo work first: wiring a React client into a small npm workspaces project — three packages, a shared calculation package, an Express API, and now a real frontend — built as the first piece of a filament cost calculator meant to eventually live inside leftfootlabs.com itself, not just as a learning exercise.

A workspace npm didn't know existed yet

Scaffolding the client with npm create vite@latest client -- --template react-ts generates its own package.json — but linking it to the shared package right afterward failed outright: No workspaces found: --workspace=@filament-calc/client. Not a typo. The workspaces field in the root package.json is a glob, and npm only rescans it at install time — its cached view of what packages exist was still whatever it was before Vite created the client's own manifest. One plain npm install from root, run once, was enough to make npm rediscover the new package before the link command would resolve.

A tsconfig with a genuinely different job

Vite's scaffolded tsconfig.app.json looks nothing like the hand-written ones behind the shared package and the Express API, and none of the differences are arbitrary. moduleResolution: "bundler" mimics how Vite and esbuild actually resolve imports rather than how Node does it directly. More significant is noEmit: true — tsc never writes a file here at all. Vite does the real transpiling; tsc only runs separately, purely to fail loudly on a type error before anything gets bundled. A genuinely different division of labor than the other two packages, where tsc itself produces the real, shippable output.

One import line, two different rules

The scaffold also turns on verbatimModuleSyntax, which requires type-only imports to be marked explicitly. Importing both a real zod schema object and a TypeScript type derived from it, from the same package, needs a visibly different treatment for each: import { type CalculationInput, CalculationInputSchema } from '@filament-calc/shared'. Miss the modifier on the type-only half and it's a real compile error — the flag exists specifically to catch importing something as a value that will never actually exist in the compiled JavaScript, since TypeScript types get erased entirely once the compiler's done checking them.

Two smaller, real deprecations turned up in the same stretch, both worth a permanent mental note: React.FormEvent as a bare type is deprecated in favor of the more specific React.SyntheticEvent<HTMLFormElement>, and zod v4 deprecated the .flatten() method on a ZodError in favor of a top-level z.flattenError() function — same output, different calling convention. Neither breaks anything today; both are worth fixing the moment they're noticed rather than let pile up.

Designing for a brand that doesn't exist yet

Since this calculator is meant to eventually sit inside leftfootLabs proper, it got its own visual identity instead of borrowing the main portfolio's palette. The subject matter did most of the real work here: this is functionally a slicer's own cost-estimate panel, so the direction leaned straight into that — a workshop-dark palette (deep charcoal, hazard-tape amber, a PETG-spool teal), a monospace face reserved specifically for the actual numeric readouts rather than used as a decorative label font, and a spec-sheet layout with a dashed receipt-stub divider separating the inputs from the results.

A couple of the actual CSS mechanisms are worth naming. font-variant-numeric: tabular-nums is what makes a column of dollar amounts genuinely line up — monospace alone doesn't guarantee every digit occupies identical width by default. color-mix(in srgb, ...) produced the button's hover state directly in CSS, with no second hex value to hand-pick and let drift out of sync with the base color later. And :focus-visible instead of plain :focus keeps the accent outline scoped to keyboard navigation specifically, not a mouse click.

The bug that wasn't a CSS bug

The panel came back rendering as plain, completely unstyled browser defaults after the stylesheet and every JSX className were supposedly in place — genuinely confusing for a moment, since neither the CSS file nor the class names looked wrong on inspection. The actual cause sat upstream of both: App.tsx had been rebuilt from a completely empty file earlier in the project, and Vite's original scaffold line, import './App.css', never made it back in through any of the rewrites since. The stylesheet existed, the classes were correctly attached to the right elements — nothing was ever loading the file that made either of those things matter. One missing import line, and everything else was already correct and just waiting to be connected.

Where it stands

A fully working, fully styled three-package monorepo exists now end to end — a validated form, a shared calculation package, an Express API, and a visual identity distinct from the main portfolio's own. The next real step isn't more monorepo mechanics; it's actually embedding this into the Rack Planner or leftfootlabs.com directly, which is a genuinely different kind of problem than building it standalone in the first place.
