Proving a Copy Is Really a Copy

The rack builder could already place shelves and devices, but it couldn't yet tell you if what you'd built actually worked — that check only existed on the server, run once at save time. Real-time feedback while building means the same rules need to run in the browser too, which raises an obvious risk: a second copy of the same logic is only useful if it's actually the same logic, not a close approximation that quietly drifts.

A port, not a reinvention

Rather than write new client-side rules from scratch, the server's own validation function got transcribed line for line — same checks, same order, same error messages, reading from already-fetched data instead of a database. The value of that approach is entirely in how strictly "line for line" gets held to. A looser rewrite that captured "the general idea" of the server's rules would have been faster to write and much easier to get subtly wrong in a way nobody would notice until a real layout disagreed with itself between the browser and the save button.

Trusting it meant testing it against itself

Both versions passing their own test suites doesn't actually prove they agree with each other — it only proves each one is internally consistent with its own assumptions. The real test was running the actual server function and the new browser version against the exact same real seeded data, in the same script, with one scenario deliberately built to provoke a collision, a width failure, and a depth failure all at once. Comparing the two outputs directly, not just eyeballing that they looked similar, is what actually closes the gap between "this looks like a faithful port" and "this is a faithful port."

The first attempt at that comparison used a live server process and a separate script inserting test data — and got two different, real answers, because the two processes had opened two different database files without either one erroring. Not a validation bug at all, just a reminder that a real cross-check is only as trustworthy as its own setup; the fix was collapsing everything into one script reading from one database, removing the ambiguity instead of debugging around it.

What actually shipped

The rack builder now shows real validation feedback as shelves and devices get placed, backed by a function proven — not assumed — to match the server's real behavior byte for byte on identical input. The server still gets the final say once Save & Share exists; this is the part that lets someone catch a real problem before ever reaching for that button.
