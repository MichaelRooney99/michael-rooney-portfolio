The Problem

A homelab that couldn't tell anyone how it was doing

A five-node Proxmox cluster, four different monitoring tools, and no single place that answered "is everything actually up?" without opening three separate dashboards first. The internship needed a capstone. The homelab needed exactly this. Building a self-hosted status page — instead of reaching for an existing product — meant every architectural decision was a real one, not a config file.

The scope was never just "make a dashboard." It was: pull live data from Prometheus, the Proxmox API, Zabbix, and a UPS, normalize four genuinely different data shapes into one consistent view, and do it without ever exposing a single real credential to the browser.

The Decision That Mattered Most

A proxy that exists to say no

Everything in a browser is public. An API token stored in a React app is visible to anyone who opens DevTools. So a small Express server sits between the client and every real data source — it holds the actual Proxmox token and Zabbix credentials, and the browser never sees any of them.

The part that took real judgment wasn't building the proxy — it was restricting it. Every route is allowlisted to the exact path and method the app actually calls, not just forwarded wholesale. Without that, a public request could reach anything those credentials are allowed to touch, not just the read-only status checks this app was ever meant to expose. That distinction — a proxy that forwards everything versus a proxy that only forwards what's actually needed — is the single decision the rest of this project's security posture rests on.

Four Moments That Mattered

Not everything that looked done actually was

Infrastructure

A playbook that ran clean and broke anyway

A hardcoded power-supply value in an Ansible template passed every run without complaint — right up until a UPS client actually restarted and hit a fatal math error the syntax check had no way to catch. The other nodes looked fine purely because they hadn't restarted yet. Fixed fleet-wide before it became a real outage, not after.

Security

Three open doors, found by looking for them on purpose

A dedicated security pass turned up proxy routes that forwarded any path or method to the real upstream APIs, real credentials attached, no restriction at all. Fixed with real allowlists and confirmed with actual 403 responses from the live site — not assumed correct because the code looked right.

Real-World Testing

A live channel that went silent under real conditions

The live-update connection worked perfectly in every local test, then went quiet in production — Cloudflare's own edge was closing idle connections under two minutes, something no local environment could ever reproduce. Caught by testing against the real public tunnel, not the code in isolation.

Verification

Working in dev, invisible in production

A new feature passed every local test and still showed nothing on the live site. The client talks straight to the server in development; production routes everything through a reverse proxy, and one new endpoint never got its forward rule added. "Runs locally" and "reachable through the real public domain" turned out to be two different claims.

What's Live Today

A real product, not a demo

The status page runs in production behind a Cloudflare Zero Trust tunnel, with no inbound ports opened on the homelab network at all. A separate, independently gated deploy pipeline ships changes automatically — every push runs a real test suite, and any deploy that fails a live smoke test rolls itself back to the last known-good commit without anyone watching it happen.

The infrastructure watches itself, the deploy pipeline watches the infrastructure, and the test suite watches the code that watches all of it.
