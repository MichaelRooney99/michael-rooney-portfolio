Session 18 — A Nudge Channel, and the Silence Cloudflare Wouldn't Tolerate

The last item from 17-Frontend Polish and Realtime — and with it, the last item across all three scope docs planned back on 07-26-2026. 15-, 16-, and 17- are all fully built as of this session.

Hybrid, not the impressive version

17- lays out two real options: full SSE, where the proxy becomes the sole aggregator for all four data sources and pushes complete state to every client, or a hybrid nudge channel, where the existing client-side polling stays exactly as it is and SSE only ever signals "something changed, refetch now." Full SSE is the more architecturally impressive answer — and it's also a genuine rearchitecture, since today's aggregation logic (services/index.ts) lives entirely in the browser, and Prometheus is something only the browser has ever talked to directly, never the proxy. Hybrid gets most of the actual user-facing win — status changes feel close to instant instead of up to a minute stale — without moving where that logic lives at all. Went with hybrid, per the doc's own recommendation.

A real departure from what the doc suggested

17-'s text frames this as "the poller already ticks independently, extend it" — implying the nudge check could piggyback on poller.ts's existing 15-minute history-recording tick. Didn't do that. That interval is right for deciding how much 90-day history granularity to keep, and completely wrong for "how fast does a status change need to be noticed" — reusing it literally would mean nudges arrive up to 15 minutes late, which is slower than the 60-second polling this feature exists to beat. The nudge checker got its own interval instead — 20 seconds, decoupled entirely from history recording. Worth naming clearly as a deliberate departure from the doc's letter, in service of the doc's actual stated goal.

Narrow on purpose

The nudge checker's Prometheus query only asks two things — node up/down and UPS status flags — not the CPU, memory, runtime, or load metrics the client's own display also fetches. Those change on essentially every tick; including them would mean nudging constantly, which is worse than no nudge channel at all. A client getting told "refetch" every 20 seconds gets no real benefit over just polling every 20 seconds itself. The whole value of a nudge is that it only fires on a genuine change.

The bug testing actually found

First real test — a plain curl -N against /events — looked correct at first: connected, went quiet, which is exactly what an open stream with nothing new to report should look like. Left running a bit longer, it died: HTTP/2 stream ... INTERNAL_ERROR. Nothing in the proxy code or nginx config changed between those two states — the connection simply sat idle too long. Root cause: Cloudflare's own edge proxy has an idle-connection timeout, well under two minutes, completely independent of anything nginx or Express are configured to do. A real production infrastructure detail, not something any local dev test would ever have surfaced — this project doesn't develop against the Cloudflare tunnel, only production traffic goes through it.

Fix: a periodic : keep-alive SSE comment line, written to every connected client every 15 seconds regardless of whether anything real happened. Lines starting with : are comments by the SSE spec — EventSource ignores them entirely, so this never surfaces as a fake nudge on the client side. Purely plumbing, invisible to the actual feature. Caught a second, smaller issue along the way: the initial connection write was a bare newline, not valid SSE framing at all — harmless in practice since browsers tolerate it, but worth fixing to an actual comment line while already in this code.

Confirmed in both directions, against real infrastructure

Rather than fake a change purely at the database level, this one got tested against something real: node_exporter stopped on Murloc for a minute — not a full reboot, which would have taken Vaultwarden, Vikunja, and Homelable down with it for no reason the test needed. Prometheus's own scrape cycle caught the drop, the nudge checker's next 20-second tick caught the change, and a second curl -N terminal — left open the whole time — printed a genuine event: nudge line the moment it happened. Both browser tabs flipped to outage within the expected window. Confirmed the recovery direction the same way immediately after restarting node_exporter — a second real nudge event, both tabs back to operational. Direct evidence from the actual stream, not an inference from what the UI happened to show.

Where this leaves the whole project

Every item across 15-, 16-, and 17- — the full plan sequenced back on 07-26-2026 — is built and confirmed live. The one item left on the entire roadmap now is automated test coverage, which was never part of that plan and hasn't been scoped yet.
