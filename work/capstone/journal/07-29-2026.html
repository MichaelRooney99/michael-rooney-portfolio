Session 12 — Four Small Things, One Real Lint Chain

First session of a seven-session plan sequenced a few days back — a whole backlog of front-end polish and real-time ideas, ordered by real dependency rather than just doc number. This one was the deliberately easy start: four small, independent items, meant to clear fast before the sessions that actually need sustained focus.

Tab title and favicon, without a new asset

The idea was simple — if something's wrong, the browser tab itself should say so, visible even backgrounded. The interesting part turned out to be the favicon half. I never had a separate "alert" icon to swap in, and didn't want to go make one. Instead, the hook grabs whatever the real favicon currently is, draws it onto a canvas at runtime, and composites a small red dot on top before writing the result back as the icon's href. Works regardless of what the favicon actually looks like, and needed zero new image files.

The part actually worth verifying wasn't the alert state — it was the reset. Easy to write code that correctly adds a dot and never quite gets around to correctly removing it again. Confirmed both directions live: dot appears the instant an incident goes active, and the exact original favicon comes back the moment it's resolved.

Skeletons that don't lie about their own size

The whole point of a loading skeleton is zero layout shift when the real content arrives — a skeleton that's "close enough" in size defeats its own purpose. Pulled the actual markup for OverallHealth and ServiceRow and matched every dimension, down to leaving space for where the uptime bars will sit once real history loads in.

A counter, and a genuine three-layer lint chase

Days-since-last-incident sounds trivial — subtract two timestamps, done. First version called Date.now() directly in the component's render body, which the newer react-hooks/purity rule correctly flags: a component's render has to be a pure function of its props and state, and the system clock is about as impure as inputs get.

Obvious fix, also wrong: move the Date.now() read into a useEffect, setState with the result. That actually made things worse in a different way — a separate rule, react-hooks/set-state-in-effect, caught it immediately. Calling setState synchronously inside an effect causes a cascading second render every time, which is exactly the kind of thing React's own docs warn against under "You Might Not Need an Effect."

The actual answer was a hook I'd never had a real reason to reach for before: useSyncExternalStore. It exists specifically for reading something that lives outside React's own state — the clock, window size, localStorage — safely during render, without the purity violation and without the extra render cycle. The subscribe callback doesn't even need to do anything here, since the component already re-renders every time new incident data arrives from the normal 60-second poll — plenty fresh for something that only needs day-level precision. Small component, but a genuinely useful pattern to have actually used once instead of just read about.

Documenting what already existed

The fourth item wasn't code at all — the proxy has had /health, /incidents, and /history/:serviceId for a while now, and none of it was written down anywhere as "here's the public API." Added a real section to the README with example requests and response shapes. Found and fixed two other stale spots in the same file while I was in there — an "uptime history" section still claiming two categories were placeholder-only weeks after that stopped being true, and a project-structure tree missing basically everything built across the last several sessions. Cheap to fix, easy to miss if nobody's actually reading the README start to finish.

Where things stand

All four confirmed live, not just locally — including watching the incident counter flip from a red 0 to a green 6 the moment the last open incident got marked resolved, and the tab's title and favicon settle back to normal in the same instant. Session 2 is next: building the actual color-token system and a light/dark toggle together, so that piece only gets built once instead of twice later during the full visual restyle.
