N10-009 Study Notes: Networking Concepts

This is the first in a five-part series of study notes I'm writing while preparing for the CompTIA Network+ exam. The goal is dual-purpose: to cement my own understanding by writing it out, and to give anyone following a similar path — homelabber, career-switcher, or just someone curious about networking — a practical anchor for concepts that can otherwise feel abstract. Each entry covers a domain from the N10-009 exam, followed by a section on how I see that domain reflected in my own lab.

Domain 1, Networking Concepts, is weighted at 23% of the exam. It's the foundation everything else builds on — the vocabulary, the models, the addressing schemes. You won't build anything correctly if this part is shaky.

The OSI Model

The OSI model is a seven-layer framework that describes how data moves across a network. It exists to give engineers a shared language for describing where something happens — and therefore where to look when something breaks. The layers, from bottom to top: Physical, Data Link, Network, Transport, Session, Presentation, Application.

The mnemonic most people learn is "Please Do Not Throw Sausage Pizza Away." What matters for the exam — and for real troubleshooting — is understanding what each layer is responsible for and what kind of device or protocol lives there.

The TCP/IP model condenses this into four layers — Network Access, Internet, Transport, and Application — and is what actually underpins modern networking. The OSI model is the exam framework; TCP/IP is what your packets are actually using. Know both, understand why they differ.

TCP vs. UDP

At Layer 4, everything is either TCP or UDP. TCP is connection-oriented — it establishes a session with a three-way handshake (SYN, SYN-ACK, ACK), guarantees delivery, and retransmits dropped packets. UDP is connectionless — it fires packets without a handshake and doesn't check whether they arrived.

Neither is better. They're appropriate for different things. TCP is right for anything where accuracy matters more than speed: web traffic, file transfers, SSH sessions. UDP is right for anything where speed matters more than perfection: video streaming, DNS queries, VoIP, game traffic. A dropped DNS query just means you ask again. A dropped video frame is just a blip. A dropped piece of a file download corrupts the file.

Ports and Protocols

Ports are how a single IP address hosts multiple services simultaneously. When a packet arrives at an IP address, the port number tells the OS which application should receive it. Port numbers run from 0 to 65535. Well-known ports are 0–1023 and require elevated privileges to bind. Registered ports are 1024–49151. Ephemeral ports (49152–65535) are assigned temporarily to client connections.

IPv4 Addressing and Subnetting

Every device on an IP network has a 32-bit address written in dotted-decimal notation — four octets separated by periods, each ranging from 0 to 255. The address has two parts: the network portion, which identifies the subnet, and the host portion, which identifies the specific device. A subnet mask tells you where that boundary falls.

CIDR notation (/24, /25, /16, etc.) is just a shorthand for the subnet mask — the number after the slash is how many bits are set to 1 in the mask. A /24 mask is 255.255.255.0: 24 bits for the network, 8 bits for hosts, giving you 256 addresses (254 usable — the network address and broadcast address are reserved).

Subnetting math requires converting Host bits (h) and Network bits (n) into usable host and subnet configurations.

1. Usable Hosts per Subnet:

H = 2h - 2

Where h is the number of remaining 0s (host bits) in the 32-bit subnet mask.

2. Number of Subnets Created:

S = 2n

Where n is the number of borrowed 1s (network bits) from the default classful boundary.

Subnetting — the practice of dividing a network into smaller segments — is the skill the exam tests most directly under time pressure. Given a network address and a subnet mask, you need to calculate the network address, broadcast address, usable host range, and number of hosts quickly. This is not something you reason through on exam day. It's something you drill until it's mechanical.

NAT and Why Private Addresses Work

Private addresses can't be routed on the internet — nothing outside your network knows how to reach 10.10.10.55. Network Address Translation is what bridges the gap. Your router maintains a translation table and rewrites the source address on outbound packets to its own public IP, then rewrites the destination address on inbound reply packets back to the original private address. From the internet's perspective, all traffic originates from one IP. From your network's perspective, every device has its own address.

DNS and DHCP

DNS translates human-readable names into IP addresses. When you type grafana.michaelrooney.dev, your OS queries a DNS resolver, which returns the IP address the name maps to. DNS uses port 53, travels over UDP for standard queries (fast, low overhead), and falls back to TCP for responses too large to fit in a single UDP packet or for zone transfers between DNS servers.

Key DNS record types: A records map a hostname to an IPv4 address. AAAA records map to IPv6. CNAME records are aliases — one name pointing to another. MX records specify mail servers for a domain. TXT records carry arbitrary text, commonly used for domain verification and email authentication (SPF, DKIM).

DHCP handles IP address assignment automatically. A client broadcasts a DHCPDISCOVER on the network, a DHCP server responds with a DHCPOFFER containing an IP lease, the client accepts with a DHCPREQUEST, and the server confirms with a DHCPACK. The DORA sequence — Discover, Offer, Request, Acknowledge — is worth knowing by name.

IPv6

IPv4's 32-bit address space gives roughly 4.3 billion addresses — exhausted in practice. IPv6 uses 128-bit addresses written in eight groups of four hexadecimal digits separated by colons, giving an effectively unlimited address space. The exam tests IPv6 address types (unicast, multicast, anycast), the loopback address (::1), and link-local addresses (fe80::/10). NAT is generally unnecessary in IPv6 — every device can have a globally routable address.

Routing Concepts

Routing is the process of moving packets between networks. A router examines the destination IP address in each packet and consults its routing table to determine the next hop — the next device to forward the packet toward its destination. Routing tables are built through static configuration (an administrator manually defines routes) or dynamic routing protocols that let routers share topology information automatically.

The exam covers several routing protocols at a conceptual level. RIP (Routing Information Protocol) is a distance-vector protocol — routers share their full routing table with neighbors and use hop count as the metric, limited to 15 hops. OSPF (Open Shortest Path First) is a link-state protocol — routers share information about their direct connections and each router independently calculates the shortest path through the network. BGP (Border Gateway Protocol) is what the internet runs on — a path-vector protocol designed for routing between autonomous systems at massive scale.

For Network+, you don't need to configure these protocols — you need to know what they are, how they differ, and which scenario each is appropriate for. CCNA is where the configuration depth comes in.

In the Lab

Domain 1 is the most directly visible in the lab's addressing scheme. The entire homelab runs on 10.10.10.0/24 — a /24 subnet, 255.255.255.0 mask, 254 usable host addresses. Every node, every LXC, every service gets a static assignment from that range. The IP allocation table in my infrastructure notes is essentially a hand-managed DHCP reservation list — which is exactly what DHCP automates.

There's a second subnet for isolated lab and IoT traffic: VLAN 20 at 10.10.20.0/24. Two separate /24 networks on the same physical infrastructure. The OSI model makes this legible — the physical layer is shared hardware, the data link layer is where VLANs are enforced on the managed switch, and the network layer is where OPNsense does inter-VLAN routing between the two subnets. Layer separation isn't academic; it's literally how the segmentation works.

DNS is handled by Unbound running inside OPNsense. Every proxied service — grafana.michaelrooney.dev, home.michaelrooney.dev, vault.michaelrooney.dev, a dozen others — has an A record that points to NginX Proxy Manager, which then routes by hostname to the appropriate internal IP. Understanding what a DNS query actually does, step by step, makes the whole proxy setup obvious rather than magical.

NAT is why any of this reaches the internet. The ISP provides one public IP. OPNsense translates between that and the 10.10.10.0/24 private range. Every outbound connection from any node in the lab appears to the internet as coming from that single public address. Cloudflare DDNS keeps the public IP mapping current so external access still works when the ISP changes it.

Routing is OPNsense's primary job. Every packet leaving a node hits the gateway at 10.10.10.1, which consults its routing table and forwards accordingly — out to the internet, across to VLAN 20, or to another host on the same subnet. When the OPNsense VM went down during a firewall rule misconfiguration, nothing in the lab could route anywhere. That's a live demonstration of what a router actually does: without it, hosts on the same switch can still reach each other at Layer 2, but anything requiring Layer 3 routing stops completely.

Tailscale adds another layer on top of all of this — a mesh VPN overlay that builds encrypted tunnels between devices regardless of their physical network location. It operates at Layer 3, assigning each device an address in the 100.64.0.0/10 range and routing traffic between them through those tunnels. The out-of-band access entry in my infrastructure notes — Tailscale at 100.64.0.78 as the recovery path when OPNsense is unreachable — is exactly the kind of network resilience thinking that troubleshooting questions on the exam are built around.
