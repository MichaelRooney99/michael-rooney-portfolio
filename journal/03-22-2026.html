Rebuilding the Portfolio

The original portfolio was functional but felt generic — Inter font, blue accent, standard dark background. It got the job done but didn't have a point of view. This week I rebuilt the whole thing from scratch while keeping all the existing content intact.

Design direction

The brief I gave myself was minimal but with strong motion, dark with warm tones, and unexpected typography. I landed on DM Serif Display for headings paired with DM Sans for body text. The serif gives the site an editorial quality that feels more considered than the usual developer portfolio aesthetic. The accent color shifted from blue to a terracotta orange — warm, distinctive, not trying to look like every other dark-mode site.

Choosing a typeface that surprises does more for a portfolio's memorability than any amount of animation.

What changed structurally

The layout got more intentional — projects now use a three-column grid with number, content, and a pill link. About and Skills sit side by side. Contact became full-width rows with animated arrow labels. The nav gets a subtle bottom border on scroll so it doesn't feel disconnected from the content as you move through the page.

All styles were centralized into a single stylesheet with clear section comments. The previous version had inline style blocks scattered across individual HTML files which made maintenance messy. Everything now inherits from one place.

Adding the Journal

The bigger addition was a public journal section — a place to write about what I'm building and learning without it being a formal case study. The index page has tag-based filtering across four categories: Homelab, Learning, Projects, and Certs. Filtering is pure client-side JavaScript with no framework or build step required.

Writing for a public audience, even a small one, forces a different kind of clarity than private notes. You can't rely on shorthand or assume context. That discipline is worth something even if nobody reads it.

The security consideration

Early drafts of the homelab journal entries included specific internal IP addresses, device names, and VPN configuration details. Publishing that would have handed anyone reading it a detailed map of the network. The fix was straightforward — sanitize IPs to generic references, remove device names, keep the concepts and lessons. The value of the writing is in what was learned, not the specific addresses involved.

What's next for the site

  • Add more journal entries as projects complete
  • Add homelab infrastructure section to About once the internship is secured
  • Update project list as coursework and personal projects accumulate
