April 23, 2026 Homelab

Never Locked Out Again

Earlier tonight a Proxmox update stopped OPNsense and took the entire subnet dark with it. I got back in through a monitor and keyboard plugged directly into the machine. It worked, but it shouldn't have to be that way — especially for something that could just as easily happen at 2am or when I'm not home.

Once the network was back up I sat down and fixed the structural problem. The goal was simple: make sure that if OPNsense ever stops again, I have a remote path back into the Proxmox host that doesn't depend on OPNsense being up.

The failure domain problem

I already run Tailscale in the homelab — there's an LXC on the Network node that acts as an exit node for the Tailnet. The obvious instinct is to use that for remote access. The problem is that the Tailscale LXC was sitting on the same node as OPNsense, getting its routing through OPNsense like everything else on the subnet. When OPNsense goes down, the Tailscale LXC loses its network path at the same moment I lose SSH access. They're in the same failure domain — one event takes both out simultaneously.

A backup access method that fails at the same time as the thing it's backing up isn't a backup. It's an illusion of one.

The fix has two parts: move the Tailscale exit node to a different node, and install Tailscale directly on the Proxmox host itself.

Migrating the exit node

Since the Network node is standalone and not part of the cluster, there's no live migration available for its LXCs. The process is backup and restore — straightforward, just not instantaneous.

I backed up the Tailscale LXC to Proxmox Backup Server on Dega, then restored it as a new container on Ankhh — the primary cluster node. The restored container came up with the same IP, the same TUN device passthrough, the same auth credentials, and the same exit node advertisement. Everything carried over from the backup cleanly.

One snag during startup: the restored container initially showed offline in tailscale status. The cause was the old LXC still running on Node 0 — two instances sharing the same Tailscale identity were conflicting. Stopping the old one resolved it immediately. The new container came up clean and has been stable since.

The old LXC is sitting stopped on Node 0 with auto-start disabled. I'll leave it there for a few days as a fallback before removing it.

Tailscale on the host

Moving the exit node to Ankhh solves the exit node's resilience, but it doesn't give me direct access to the Network node specifically. For that, I installed Tailscale directly on the Proxmox host — not in a container, on the host itself. 

curl -fsSL https://tailscale.com/install.sh | sh
tailscale up --hostname=proxmox-network

The host install runs as a systemd service and starts on boot. It doesn't advertise an exit node or any subnet routes — its only job is to give the host a stable Tailscale IP address that's reachable from anywhere on the Tailnet regardless of what's happening on the LAN.

The next time OPNsense stops and takes the subnet with it, recovery looks like this from any device on the Tailnet: 

ssh root@proxmox-network

That's it. That connection routes entirely through Tailscale's network, bypasses 10.10.10.0/24 completely, and lands directly on the Proxmox host. From there I can start OPNsense, fix whatever broke, and be done — without touching a keyboard plugged into the machine.

Where things stand

The Tailscale exit node is on Ankhh, outside OPNsense's failure domain. The Network node has a permanent out-of-band management path via Tailscale on the host. Physical console access is still there as a last resort, but it's no longer the first resort.

Tonight started with a lockout and ended with infrastructure that's meaningfully harder to get locked out of. That's a reasonable outcome for a few hours of frustration.
