May 16, 2026 Projects

Overdue Housekeeping

Not every session involves standing up a new service or debugging something that broke at midnight. Sometimes it's the quieter work — the things that have been sitting on the list long enough that they start to feel like background noise. Today was that kind of session. The portfolio project list had gotten long enough to feel unwieldy, several coursework projects had no public home yet, the sitemap had a stale entry, and the local repo structure had been scattered across a few directories for longer than I'd like to admit.

A dedicated portfolio page

The homepage work section was never designed to be a full project list. It was always meant to be a teaser — two or three entries and a link to somewhere more complete. But it had gradually absorbed every project as they were added, and it was starting to feel like a wall before you got to the journal or the about section.

The fix was finishing something I'd already started. portfolio-showcase.html had been scaffolded for a while with placeholder content. Today it got wired up properly — all four current projects using the same .project article pattern as the rest of the site, so no new CSS was needed. The homepage work section is now trimmed to two teaser entries and a "See Full Portfolio" banner that mirrors the existing journal banner. Same component, different destination.

The nav Work link now points directly to portfolio-showcase.html rather than anchoring to #work on the homepage. On the showcase page the Work link carries the active state. Small things, but they matter for communicating where you are.

New projects added

Three coursework projects that had been sitting unlinked finally made it in. Two were for a Willow Gardens community garden concept — a fictional multi-page site built once with Bootstrap 5 and once rebuilt from scratch with Tailwind CSS. The point of doing it twice was the comparison: component-based styling versus utility-first, same design goals, different mental models. Both are multi-page sites with accessible navigation, a plot application form with validation, resource listings, and gardening tips.

The third was a Star Wars Faves app built collaboratively with classmates as part of a front-end course. It pulls live character data from the Star Wars API, manages checkbox state with Angular signals, and posts selected favorites to a Microsoft Teams channel via a Power Automate webhook. Each student implemented their own component on the same routing structure — a useful exercise in working within a shared codebase without stepping on each other.

None of these got a middle-man detail page. The view project links go straight to the deployed GitHub Pages URLs. An extra click to read a description of something you could just be looking at doesn't serve anyone.

Sitemap cleanup

The sitemap had a stale entry for /work/quickbites-kiosk.html — a detail page removed a while back when the project link was changed to go directly to the live site. That got pulled. I also briefly went down the road of adding lastmod dates to every entry before remembering that Google has largely ignored that field for years unless it's accurate and consistently maintained — a stale or estimated date is actively worse than omitting it. Stripped it back out. The sitemap is now just loc and priority, which is all it ever needed to be.

The showcase page was already listed from when it was first scaffolded, so no new entries were needed there. External GitHub Pages deployments don't go in the sitemap — those are separate domains that get indexed on their own.

Local repo organization

More administrative than technical, but worth putting in writing: the local directory structure for project repos got consolidated. They had accumulated across a few different locations over time — some in one folder, some in another, no consistent logic to any of it — and it had gotten hard to find things quickly.

The reassuring thing about Git is that moving a local directory doesn't affect the remote at all. The .git folder travels with the directory, and the remote connection lives inside it. Push and pull work exactly the same from the new location. The only things that needed updating were VS Code's recent projects list and a couple of terminal aliases pointing at old paths.

What's next

The portfolio is in a cleaner state than it's been in a while. The Willow Gardens Tailwind version still needs a deployed URL before it's fully wired up, and the homepage hero copy could use a pass now that the work section has changed shape. Beyond that, the focus goes back to Network+ prep — the site maintenance was genuinely overdue, but it doesn't move the cert needle, and that's where the energy needs to be.
