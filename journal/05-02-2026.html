May 2, 2026 Homelab Learning

Proactive Alerts

With the metrics infrastructure finally stable, today was about turning that data into action. A dashboard is only useful if you're looking at it; an alert finds you when you aren't. I moved the lab into a proactive state by wiring Grafana into Gmail and writing custom PromQL to watch the most critical parts of the stack.

Data Enrichment

The first task was fixing the "cryptic IP" problem. While I know my subnet mapping by heart, alert emails shouldn't require a lookup table. I updated the prometheus.yml to include friendly_name labels for every target. Now, instead of an alert for 10.10.10.57, I get a notification for Node-02-Shasta.

The SMTP Hurdle

Configuring Grafana to send mail from a Docker container running in an LXC turned out to be a lesson in environment variable priority. I opted to pass the SMTP configuration directly through the Docker Compose file rather than modifying the grafana.ini.

Because I use 2FA on my Google account, a standard password was out of the question. Generating a 16-character App Password was the key to getting the test notification to finally turn green.

Logic in Code

I skipped the Grafana "Builder" UI in favor of writing direct PromQL. It's cleaner and more predictable. I stood up three primary alert rules:

  • Node Vitality: Watching for up == 0 across the node_exporter job.
  • Power Loss: Triggering on nut_ups_status == 2 (On Battery).
  • Shutdown Imminent: A critical alert when nut_battery_runtime drops below 300 seconds.

One major realization: Prometheus queries that return "No Data" for an alert like up == 0 are exactly what you want to see. It means the condition for failure hasn't been met.

Final Polish

To avoid "alert fatigue" from minor network blips, I implemented a 2-minute "Pending" period. The system waits to ensure a node is actually down before buzzing my phone. The lab now feels less like a collection of parts and more like a managed environment.
